Reseller API · v1

GPT UPI QR API

Turn a ChatGPT session into a scannable UPI payment link — programmatically, at whatever volume your business runs at. You send the session, we run the full extraction pipeline, you get back a payment URL.

Overview

The API is the automation channel for the GPT UPI QR Creator. It is built for partners who need links produced on demand from their own systems, without anyone opening an app.

  • Bring your own sessions. You supply the ChatGPT session; we never need an account from you, and we do not retain the session after the job finishes.
  • Prepaid, per-result pricing. Credits are spent only on links actually delivered. A failed creation is refunded in full, automatically.
  • Two calls, one flow. Submit, then poll. No webhooks to host, no callbacks to whitelist, no SDK to install.
  • Idempotent by design. Attach your own reference to a creation and a retried request replays the original result instead of billing you twice.

Quick start

Base URL — /api/upi (or https://your-domain.com/api/upi)

  1. In your admin dashboard or app, issue a UPI Reseller API Key. Your key is issued once and stays fixed.
  2. Top up your credit balance or issue custom credits in the admin panel.
  3. Submit a creation, then poll the order until it reports completed or failed.
# 1 — submit creation
curl -X POST https://your-domain.com/api/upi/v1/create \
  -H "Authorization: Bearer upi_live_<your-key>" \
  -H "Content-Type: application/json" \
  -d '{"session_json":"<ChatGPT session JSON>","reference":"order-1001"}'

# Response:
# { "ok": true, "status": "processing",
#   "order_code": "UPI-9F2A1B7C4D", "poll_after_sec": 15 }
// 1 — submit creation in JS (Node / Browser)
const response = await fetch('/api/upi/v1/create', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer upi_live_<your-key>',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    session_json: '<ChatGPT session JSON>',
    reference: 'order-1001'
  })
});
const data = await response.json();
console.log(data.order_code);
# 1 — submit creation in Python
import requests

res = requests.post(
    'https://your-domain.com/api/upi/v1/create',
    headers={'Authorization': 'Bearer upi_live_<your-key>'},
    json={'session_json': '<ChatGPT session JSON>', 'reference': 'order-1001'}
)
order = res.json()
print(order['order_code'])
// 1 — submit creation in PHP
$ch = curl_init('https://your-domain.com/api/upi/v1/create');
curl_setopt($ch, CURLOPT_HTTPHEADER, [
    'Authorization: Bearer upi_live_<your-key>',
    'Content-Type: application/json'
]);
curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode([
    'session_json' => '<ChatGPT session JSON>',
    'reference' => 'order-1001'
]));
curl_setopt($ch, CURLOPT_RETURNTRANSFER, true);
$res = json_decode(curl_exec($ch), true);
echo $res['order_code'];
# 2 — poll until it settles
curl https://your-domain.com/api/upi/v1/order/UPI-9F2A1B7C4D \
  -H "Authorization: Bearer upi_live_<your-key>"

# Response:
# { "ok": true, "status": "completed",
#   "payment_url": "https://payments.stripe.com/upi/instructions/..." }
// 2 — poll status in JS
const pollRes = await fetch('/api/upi/v1/order/UPI-9F2A1B7C4D', {
  headers: { 'Authorization': 'Bearer upi_live_<your-key>' }
});
const orderStatus = await pollRes.json();
console.log(orderStatus.payment_url);
# 2 — poll status in Python
res = requests.get(
    'https://your-domain.com/api/upi/v1/order/UPI-9F2A1B7C4D',
    headers={'Authorization': 'Bearer upi_live_<your-key>'}
)
status = res.json()
print(status.get('payment_url'))

Authentication

Send your key as a bearer token on every request. X-API-Key is accepted as an alternative for clients that cannot set an Authorization header.

HEADER FORMAT 
Authorization: Bearer upi_live_<your-key>

Treat the key as a payment credential. It spends your balance and cannot be scoped or restricted. Keep it server-side. If it is exposed, rotate it in the mini-app: the old key stops working immediately, and your balance, history and orders carry over to the new one.

Billing

Billing is prepaid, in USD, at $0.10 per successful creation. Because a creation runs asynchronously, the price is reserved when you submit and settled when the job finishes.

Outcome Effect on your balance
completed $0.10 charged. creations_done increments.
failed Refunded in full, automatically. The order carries "refunded": true.
session_rejected Never charged — the reservation is released before any work starts.
rate_limited Never charged.

You pay only for links you receive. Refunds do not depend on you polling — a background process settles abandoned orders on the same terms.

Create a link

POST /v1/create
Field Type Description
session_json string or object Required. A full ChatGPT session JSON, or a raw accessToken. Objects are serialised for you.
reference string Optional, up to 64 characters. Your own identifier for this creation. Makes the request idempotent: repeating it returns the original order rather than starting — and billing — a second one.

Response · 200

JSON RESPONSE 
{
  "ok": true,
  "status": "processing",
  "order_code": "UPI-9F2A1B7C4D",
  "reference": "order-1001",
  "price_usd": 0.1,
  "credits_remaining": 24.7,
  "poll_after_sec": 15
}

Store the order_code. It is the only handle you need for the rest of the flow, and the only identifier support will ask for.

Order status

GET /v1/order/{order_code}

Poll until status is no longer processing. Every 10–15 seconds is the right cadence; most creations settle in one to two minutes.

Completed

STATUS: COMPLETED 
{
  "ok": true,
  "status": "completed",
  "order_code": "UPI-9F2A1B7C4D",
  "payment_url": "https://payments.stripe.com/upi/instructions/CDQQARoXChVh...",
  "price_usd": 0.1,
  "credits_remaining": 24.7
}

Hand payment_url to the payer directly, or render it as a QR code. A UPI user in India scans it and confirms the payment within five minutes.

Failed

STATUS: FAILED 
{
  "ok": false,
  "status": "failed",
  "order_code": "UPI-9F2A1B7C4D",
  "error": "creation_failed",
  "message": "Creation failed. Refresh the ChatGPT session and try again. You were not charged.",
  "refunded": true,
  "credits_remaining": 24.8
}

Two outcomes are possible, and both are safe to branch on:

error Meaning
not_eligible The account has no free-trial eligibility, or the promo was already redeemed. Use a different account — retrying this one will not help.
creation_failed Anything else. Retry with a fresh session; these are usually transient.

Either way the creation is refunded, so a retry costs nothing.

Error reference

Errors are JSON with a stable error code and a human-readable message. Branch on the code; log the message.

HTTP error Meaning
400 bad_request
bad_session		 Missing or malformed session_json. Not charged.
401 unauthorized Key missing, invalid or deactivated.
402 insufficient_credits Balance below $0.10. Top up in the mini-app; the API cannot run on an empty balance.
409 conflict That reference already belongs to a live order.
422 session_rejected
not_eligible		 The session was refused before any work started — expired, or the account is not promo-eligible. Not charged.
429 rate_limited Three creations are already in flight on this key. Not charged.
429 too_many_failures Too many failed creations on this key in the last hour. Review the sessions you are sending before retrying.

Operational notes

  • Concurrency — three creations in flight per key. Further submissions receive 429 rather than queueing, so retry scheduling stays under your control.
  • Capacity — creations run on a shared worker pool. Under load a job may wait briefly for a slot; this appears as a longer processing phase, never as an error.
  • Timeout — an order that has not settled within ten minutes is closed as failed with error: "timeout" and refunded.
  • Session quality drives results. Fresh, eligible sessions convert; stale ones do not. Retrying a failure with a new session is the correct response and costs nothing.
  • Data retention — we store the resulting link and order metadata. The session you post is used for the run and not kept.
  • History — every order stays queryable under your key for as long as the key exists.
